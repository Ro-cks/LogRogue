# LogRogue

장비 프로그램이 날짜별로 쌓는 로그 폴더를 압축해 보관하고, 원하면 원본을 삭제해 디스크 공간을 확보하는 Windows 트레이 유틸리티입니다. 부팅 시 자동으로 켜져 정해진 시각에 스스로 백업합니다.

> 현재 버전: **1.0.0.0**

## 주요 기능

**압축과 보관**
- 기간에 해당하는 날짜 폴더를 ZIP으로 압축
- 압축 단위 선택: 일별 / 주별(월~일) / 월별 / 선택 기간 전체
- 같은 이름의 압축 파일이 있으면 기존 내용에 새 날짜를 합쳐서 갱신
- 압축 후 무결성 검증 (파일 개수·이름·압축 해제 크기를 원본과 대조)

**원본 삭제 (선택)**
- 휴지통 이동 또는 영구 삭제
- 압축과 검증에 성공한 날짜만, 안전 확인을 모두 통과했을 때만 삭제

**기간 지정**
- 지정한 기간 (시작일 ~ 종료일)
- 최근 N일만 남기고 그 이전 전부 — 실행 시점에 매번 다시 계산되므로 예약 실행에 적합

**자동 실행**
- 예약 실행: 매일 / 매주 요일 지정 / N시간마다
- PC가 꺼져 있어 지나간 예약은 켜진 뒤 한 번만 보충 실행 (끌 수 있음)
- Windows 로그인 시 자동 시작, 창 없이 트레이에서 대기
- 중복 실행 방지 — 이미 실행 중이면 기존 창을 띄우고 종료

**운영 편의**
- 트레이 상주, 창을 닫거나 최소화하면 트레이로 숨김
- 압축 전 확인 창에서 만들어질 압축 파일 목록을 미리 확인
- 작업 이력 (최근 200건) 과 프로그램 동작 로그
- 설정 자동 저장

텍스트 로그 기준으로 **약 90% 이상** 용량이 줄어듭니다. (샘플 13일치 76.5 MB → 5.8 MB)

## 대상 로그 폴더 구조

대상 폴더 바로 아래에 `yyyy-MM-dd` 형식의 날짜 폴더가 있는 구조를 전제로 합니다.

```
대상 폴더\
├── 2026-08-17\
│   ├── globalfile\2026-08-17_global.log
│   ├── errorfile\2026-08-17_error.log
│   ├── eventfile\ER_0807_PRsInspResultErr.log
│   └── ...
├── 2026-08-18\
└── ...
```

- 기간 판정은 파일명이 아니라 **날짜 폴더명** 기준입니다. 파일명에 날짜가 없는 로그도 누락되지 않습니다.
- 날짜 형식이 아닌 폴더는 무시합니다.
- 압축 파일 안에서도 날짜 폴더 구조가 유지되어, 압축을 풀면 원래 모양 그대로 복원됩니다.

## 압축 단위와 파일 이름

| 단위 | 압축 파일 이름 |
|---|---|
| 일별 | `2026-08-20.zip` |
| 주별 | `2026-08-17_2026-08-23.zip` (그 주 월요일~일요일) |
| 월별 | `2026-08.zip` |
| 선택 기간 전체 | `2026-08-17_2026-09-09.zip` (실제 포함된 첫 날~마지막 날) |

주별·월별은 실제로 로그가 있는 날이 아니라 **달력 기준**으로 이름을 정합니다. 그래야 나중에 같은 주·같은 달의 다른 날을 압축할 때 같은 파일에 합쳐집니다.

예약 실행으로 매일 하루치씩 월별 압축을 하면, 한 달 내내 `2026-08.zip` 하나에 계속 누적됩니다.

## 안전 설계

원본 로그를 삭제할 수 있는 프로그램이므로 아래 원칙을 지킵니다.

**오늘 날짜 폴더는 절대 건드리지 않습니다.**
장비가 기록 중인 파일이 있을 수 있으므로, 기간에 오늘이 포함되어도 오늘 및 미래 날짜 폴더는 대상에서 제외합니다.

**깨진 압축 파일을 남기지 않습니다.**
임시 파일(`.zip.tmp`)에 압축하고 검증을 통과한 뒤에만 최종 이름으로 바꿉니다. 도중에 실패하거나 프로그램이 종료되어도 출력 폴더에는 완전한 ZIP만 남습니다.

**기존 압축본의 내용을 잃지 않습니다.**
같은 이름의 압축 파일이 있으면 그 내용을 새 압축본에 모두 옮겨 담은 뒤 새 날짜를 추가하고, 전체를 검증하고 나서 교체합니다. 기존 파일이 깨져서 읽을 수 없을 때만 건드리지 않고 `_2`를 붙여 따로 저장합니다.

같은 파일이 양쪽에 있으면 더 큰 쪽을 남깁니다. 로그는 뒤에 덧붙여지기만 하므로 큰 쪽이 더 완전합니다.

**삭제 직전에 다시 확인합니다.**
원본 삭제는 그 날짜의 압축과 검증이 성공한 직후에만 수행하며, 실제로 지우기 전에 아래를 모두 재확인합니다.

1. 압축 파일이 검증 당시 크기 그대로 존재하고, 이 날짜가 그 압축 파일에 포함되어 있는가
2. 지우려는 폴더가 대상 폴더 바로 아래의 날짜 폴더인가
3. 오늘 이전 날짜인가
4. 폴더 안의 파일을 다른 프로그램이 사용하고 있지 않은가

하나라도 어긋나면 그 날짜는 삭제하지 않고 사유를 결과와 이력에 남깁니다.

**묶음 단위로 실패를 격리합니다.**
한 압축 파일에 들어갈 날짜 중 하나라도 문제가 있으면 그 묶음 전체를 실패로 처리하고, 그 묶음의 원본은 하나도 지우지 않습니다. 다른 묶음은 정상 진행됩니다.

**출력 폴더는 대상 폴더 밖에 있어야 합니다.**
출력 폴더가 대상 폴더와 같거나 그 안에 있으면 실행을 거부합니다.

## 삭제 방식

| 방식 | 특징 |
|---|---|
| 휴지통으로 이동 | 실수 시 되살리기 쉬움. **휴지통을 비우기 전까지 디스크 공간은 확보되지 않음** |
| 영구 삭제 | 즉시 공간 확보. 되돌리려면 ZIP에서 복원 |

- 네트워크 드라이브처럼 휴지통이 없는 위치이거나 휴지통 용량보다 큰 경우, Windows가 휴지통 이동을 영구 삭제로 처리합니다.
- 수동 실행에서 영구 삭제를 선택하면 확인 창에서 Enter 키로 실행되지 않으며, 버튼을 직접 눌러야 합니다.
- **예약 실행은 확인 창 없이 설정대로 실행됩니다.** 예약 설정 창에서 이에 대한 경고를 표시합니다.

## 저장되는 파일

모두 `%APPDATA%\LogRogue` 아래에 있습니다.

```
settings.json          설정 (경로, 기간, 압축 단위, 삭제 방식, 예약)
history.jsonl          작업 이력. 한 줄에 실행 한 건, 최근 200건 보관
logs\
  logrogue-20260923.log   프로그램 동작 로그. 날짜별, 14일 보관, 파일당 5MB 상한
```

설정 파일이 손상되면 기본값으로 시작하고, 손상된 파일은 지우지 않고 `settings.json.broken-날짜시각`으로 보관합니다.

## 실행 환경

- Windows 10 / 11 (x64)
- .NET 10 (자체 포함으로 게시하면 별도 설치 불필요)

## 빌드와 배포

### 요구 사항

- Visual Studio 2022 (최신 업데이트) 또는 Visual Studio 2026
- **.NET 데스크톱 개발** 워크로드
- .NET 10 SDK

### 개발 중 실행

`LogRogue.sln`을 열고 `LogRogue.App`을 시작 프로젝트로 둔 뒤 F5.

> Ctrl+F5로 실행한 뒤 창을 닫으면 트레이에 남아 있습니다. 다음 빌드에서 exe가 잠겨 실패하므로 트레이 메뉴의 [종료]로 끄고 빌드하세요.

### 단일 실행 파일 게시

솔루션 폴더에서:

```
dotnet publish LogRogue.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

결과물: `LogRogue.App\bin\Release\net10.0-windows\win-x64\publish\Log Rogue.exe`

- `-p:EnableCompressionInSingleFile=true` — 파일 크기가 줄지만 시작이 약간 느려집니다.
- `PublishTrimmed`는 WinForms에서 지원되지 않으므로 사용하지 마세요.

### 설치 파일 만들기

[Inno Setup](https://jrsoftware.org)으로 `installer\LogRogue.iss`를 컴파일(F9)하면 설치 파일이 만들어집니다. 게시를 먼저 해야 합니다.

- 설치 중 프로그램이 실행 중이면 종료를 안내합니다.
- 제거 시 자동 실행 등록도 함께 지웁니다.
- 설정·이력·로그는 제거해도 남습니다.

> 서명하지 않은 실행 파일은 SmartScreen 경고가 뜨고 백신이 오탐할 수 있습니다. 트레이 상주 + 자동 실행 + 파일 삭제 조합이 행위 기반 탐지에 걸리기 쉽습니다.

## 사용 방법

1. **대상 폴더**에 날짜 폴더들이 들어 있는 로그 루트 폴더를 지정합니다.
2. **출력 폴더**에 압축 파일을 저장할 위치를 지정합니다. (대상 폴더 밖)
3. **기간**과 **압축 단위**를 고릅니다.
4. 원본을 지우려면 **원본 삭제**를 체크하고 방식을 고릅니다.
5. **실행**을 누르면 확인 창이 뜹니다. 만들어질 압축 파일 목록을 확인하고 시작합니다.

예약 실행을 쓰려면 **예약 설정**에서 주기를 정하고, 기간은 **"최근 며칠 제외 전부"**로 두세요. 지정한 기간으로 두면 매번 같은 날짜 범위를 다시 처리하게 됩니다.

> 처음 사용할 때는 실제 로그 폴더를 복사한 사본으로 먼저 테스트하는 것을 권장합니다.

## 프로젝트 구조

```
LogRogue.sln
├── LogRogue.Core            UI와 무관한 핵심 로직
│   ├── Scanning\            날짜 폴더 탐색, 기간 판정, 용량 표시
│   ├── Archiving\           압축 단위 묶기, 압축·병합·검증
│   ├── Deletion\            삭제 전 안전 확인, 휴지통 이동, 영구 삭제
│   ├── Scheduling\          예약 설정과 다음 실행 시각 계산
│   ├── Settings\            설정 저장·불러오기
│   ├── History\             작업 이력 기록
│   ├── Diagnostics\         프로그램 동작 로그
│   ├── Startup\             Windows 자동 실행 등록
│   ├── BackupJob.cs         전체 흐름 (Prepare → Run)
│   ├── BackupPeriod.cs      기간 계산
│   └── AppPaths.cs          파일 저장 위치
│
├── LogRogue.App             WinForms 화면
│   ├── Form1.cs             메인 창
│   ├── Form1.Tray.cs        트레이 상주와 닫기 처리
│   ├── Form1.Schedule.cs    예약 실행
│   ├── PreviewForm.cs       압축 전 확인 창
│   ├── ScheduleForm.cs      예약 설정 창
│   ├── HistoryForm.cs       작업 이력 창
│   ├── SingleInstance.cs    중복 실행 방지
│   └── Program.cs           시작 지점
│
└── LogRogue.Core.Tests      단위 테스트 (xUnit)
```

핵심 로직은 `LogRogue.Core`에 모여 있고 화면은 이를 호출만 합니다. 예약 실행과 수동 실행이 같은 로직을 그대로 재사용하며, 이후 명령줄 실행을 붙일 때도 마찬가지입니다.
