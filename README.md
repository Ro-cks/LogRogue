# 로그로그 (LogRogue)

여러 프로그램이 쌓는 로그를 폴더별로 압축해 보관하고, 원하면 원본을 삭제해 디스크 공간을 확보하는 Windows 트레이 유틸리티입니다. 부팅 시 자동으로 켜져서 작업마다 정해진 시각에 스스로 백업합니다.

> 현재 버전: **0.2.0**

## 주요 기능

**작업 단위 관리**
- 로그 폴더마다 **작업**을 따로 만들어 관리
- 작업마다 대상 폴더, 출력 폴더, 기간, 압축 단위, 삭제 방식, 예약을 각자 설정
- 작업끼리 서로 해치는 설정(대상 폴더 겹침, 출력 폴더 공유 등)은 저장 단계에서 차단

**어떤 형태의 로그든**
- 대상 폴더 아래의 **모든 파일**을 하위 폴더까지 훑어 **파일의 수정한 날짜**로 판정
- 날짜별 폴더에 나눠 쌓이는 로그든, 한 폴더에 계속 쌓이는 로그든 똑같이 처리
- 파일 이름이나 폴더 이름에 날짜가 없어도 동작

**압축과 보관**
- 압축 단위 선택: 일별 / 주별(월~일) / 월별 / 선택 기간 전체
- 같은 이름의 압축 파일이 있으면 기존 내용에 새 날짜를 합쳐서 갱신
- 매일 같은 이름으로 새로 생기는 로그(`app.log` 등)도 서로 덮어쓰지 않고 모두 보존
- 압축 후 무결성 검증 (파일 개수·이름·압축 해제 크기를 원본과 대조)

**원본 삭제 (선택)**
- 휴지통 이동 또는 영구 삭제
- 압축과 검증에 성공한 파일만, 파일마다 안전 확인을 거쳐 삭제
- 파일을 지우고 비게 된 하위 폴더도 정리

**자동 실행**
- 작업마다 예약: 매일 / 매주 요일 지정 / N시간마다
- 여러 작업의 예약이 겹치면 차례대로 하나씩 실행
- PC가 꺼져 있어 지나간 예약은 켜진 뒤 한 번만 보충 실행 (끌 수 있음)
- Windows 로그인 시 자동 시작, 창 없이 트레이에서 대기
- 중복 실행 방지 — 이미 실행 중이면 기존 창을 띄우고 종료

**운영 편의**
- 작업 목록에서 예약, 다음 실행 시각, 마지막 결과를 한눈에 확인
- 트레이 상주, 창을 닫거나 최소화하면 트레이로 숨김
- 압축 전 확인 창에서 만들어질 압축 파일 목록을 미리 확인
- 작업 이력 (최근 200건, 작업별 구분) 과 프로그램 동작 로그
- 정보 창에서 버전 확인과 데이터 폴더 바로가기

텍스트 로그 기준으로 **약 90% 이상** 용량이 줄어듭니다. (샘플 13일치 76.5 MB → 5.8 MB)

## 날짜 판정 방식

대상 폴더 안의 파일마다 **수정한 날짜**를 봅니다. 폴더 이름, 폴더 날짜, 파일 이름은 보지 않습니다.

```
대상 폴더\                              대상 폴더\
├── 2026-08-20\                         ├── app_20260818.log   (8/18)
│   ├── globalfile\a.log   (8/20)       ├── app_20260819.log   (8/19)
│   └── errorfile\b.log    (8/20)       ├── app.log            (오늘) ← 제외
└── 2026-08-21\                         └── debug\x.txt        (8/19)
    └── globalfile\a.log   (8/21)
```

두 구조 모두 파일 각자의 수정한 날짜로 날짜별로 묶입니다.

- **수정한 날짜가 오늘인 파일은 항상 제외**합니다. 지금도 기록 중일 수 있기 때문입니다.
- 수정한 날짜는 파일을 복사해도 바뀌지 않습니다. 반면 폴더 날짜와 만든 날짜는 복사하면 복사한 시각으로 바뀌어서 기준으로 쓰지 않습니다.
- 오래된 로그를 편집기로 열어 저장하면 수정한 날짜가 그날로 바뀝니다. 이 경우 그 파일은 한동안 대상에서 빠집니다. (지워지는 방향이 아니라 남는 방향입니다)

## 압축 단위와 파일 이름

| 단위 | 압축 파일 이름 |
|---|---|
| 일별 | `2026-08-20.zip` |
| 주별 | `2026-08-17_2026-08-23.zip` (그 주 월요일~일요일) |
| 월별 | `2026-08.zip` |
| 선택 기간 전체 | `2026-08-17_2026-09-09.zip` (실제 포함된 첫 날~마지막 날) |

주별·월별은 **달력 기준**으로 이름을 정합니다. 그래야 나중에 같은 주·같은 달의 다른 날을 압축할 때 같은 파일에 합쳐집니다. 예약으로 매일 하루치씩 월별 압축을 하면, 한 달 내내 `2026-08.zip` 하나에 누적됩니다.

압축 파일 안에는 **대상 폴더 기준의 원래 경로**가 그대로 들어가서, 풀면 원래 모양대로 복원됩니다. 같은 경로에 날짜가 다른 파일이 들어와야 하면, 기존 것에 시각을 붙여 함께 보존합니다.

```
2026-08.zip
├── logs/app (2026-08-20 180000).log
├── logs/app (2026-08-21 180000).log
└── logs/app.log
```

## 작업

작업 하나는 **대상 폴더 하나를 어떻게 백업할지**의 묶음입니다.

| 항목 | 내용 |
|---|---|
| 작업 이름 | 목록과 이력에 표시되는 이름 |
| 대상 폴더 | 로그가 쌓이는 폴더. 안의 모든 파일이 대상 |
| 출력 폴더 | 압축 파일을 저장할 폴더 |
| 기간 | 최근 N일 제외 전부 / 지정한 기간 |
| 압축 단위 | 일별 / 주별 / 월별 / 선택 기간 전체 |
| 원본 | 삭제 안 함 / 휴지통 / 영구 삭제 |
| 예약 | 주기, 시각, 놓친 예약 보충 여부, 알림 방식 |

작업끼리 아래 조합은 저장할 수 없습니다.

- **대상 폴더가 겹침** — 한쪽이 다른 쪽 안에 있으면 같은 파일을 두 작업이 압축·삭제합니다.
- **출력 폴더가 같음** — `2026-08.zip` 같은 이름이 서로 겹칩니다.
- **출력 폴더가 다른 작업의 대상 폴더 안에 있음** — 한 작업이 만든 압축 파일을 다른 작업이 로그로 알고 압축하고 지웁니다.

예약 실행 직전에도 한 번 더 확인하므로, 설정 파일을 손으로 고쳐도 위험한 조합은 실행되지 않습니다.

## 안전 설계

원본을 삭제할 수 있고 대상 폴더의 모든 파일을 다루는 프로그램이므로 아래 원칙을 지킵니다.

**위험한 위치는 대상 폴더로 지정할 수 없습니다.**
드라이브 전체, Windows·Program Files, 사용자 폴더, 바탕 화면·문서 폴더 자체, AppData, 이 프로그램의 설치 폴더와 데이터 폴더, 그리고 이들의 상위 폴더는 거부합니다. 그 아래 하위 폴더는 괜찮습니다.

**링크는 따라가지 않습니다.**
대상 폴더 안에 바깥을 가리키는 심볼릭 링크나 정션이 있어도 따라 들어가지 않고, 대상으로 삼지도 않습니다.

**깨진 압축 파일을 남기지 않습니다.**
임시 파일(`.zip.tmp`)에 압축하고 검증을 통과한 뒤에만 최종 이름으로 바꿉니다.

**기존 압축본의 내용을 잃지 않습니다.**
같은 이름의 압축 파일이 있으면 그 내용을 새 압축본에 모두 옮겨 담고 새 파일을 추가한 뒤, 전체를 검증하고 나서 교체합니다. 기존 파일이 깨져 읽을 수 없을 때만 건드리지 않고 `_2`를 붙여 따로 저장합니다.

**삭제는 두 단계로 확인합니다.**

날짜 단위로 한 번 (어긋나면 그날 파일은 하나도 지우지 않음)
1. 압축과 검증이 성공했고, 압축 파일이 그 크기 그대로 있으며, 이 날짜가 그 압축에 포함되어 있는가
2. 오늘 이전 날짜인가

파일마다 한 번 더 (어긋난 파일만 남기고 나머지는 삭제)
3. 대상 폴더 안에 있는가
4. 링크가 아닌 실제 파일인가
5. 압축한 뒤로 크기와 수정한 시각이 바뀌지 않았는가
6. 오늘 수정되지 않았는가
7. 다른 프로그램이 쓰고 있지 않은가

남긴 파일과 사유는 결과 목록과 작업 이력에 남습니다.

**묶음 단위로 실패를 격리합니다.**
한 압축 파일에 들어갈 파일 중 하나라도 압축·검증에 실패하면 그 묶음 전체를 실패로 처리하고, 그 묶음의 원본은 하나도 지우지 않습니다.

**빈 폴더 정리는 좁게 합니다.**
이번에 파일을 지운 폴더 중 완전히 비게 된 것만 정리합니다. 원래부터 비어 있던 폴더와 대상 폴더 자체는 건드리지 않습니다.

## 삭제 방식

| 방식 | 특징 |
|---|---|
| 휴지통으로 이동 | 실수 시 되살리기 쉬움. **휴지통을 비우기 전까지 디스크 공간은 확보되지 않음** |
| 영구 삭제 | 즉시 공간 확보. 되돌리려면 ZIP에서 복원 |

- 네트워크 드라이브처럼 휴지통이 없는 위치이거나 휴지통 용량보다 크면, Windows가 휴지통 이동을 영구 삭제로 처리합니다.
- 수동 실행에서 영구 삭제를 고르면 확인 창에서 Enter 키로 실행되지 않으며 버튼을 직접 눌러야 합니다.
- **예약 실행은 확인 창 없이 작업 설정대로 실행됩니다.** 예약 설정 창에서 이에 대한 경고를 표시합니다.

## 예약 실행

- 30초마다 모든 작업의 예약 시각을 확인합니다. 절전에서 깨어나거나 시스템 시각이 바뀌어도 따라잡습니다.
- 프로그램이 켜진 뒤 첫 확인은 30초 뒤에 합니다. 부팅 직후 네트워크 드라이브가 연결될 시간을 줍니다.
- 여러 작업이 동시에 때가 되면 하나씩 차례로 실행하고, 하나가 끝나면 바로 다음 작업을 이어서 실행합니다.
- PC가 며칠 꺼져 있었어도 밀린 만큼 여러 번 돌지 않고 한 번만 실행합니다.
- 작업의 주기나 시각을 바꿔 저장하면 그 시점부터 새로 계산합니다.
- 예약 실행은 기간을 **"최근 N일 제외 전부"**로 두어야 매번 알맞은 범위가 잡힙니다.

## 저장되는 파일

모두 `%APPDATA%\LogRogue` 아래에 있습니다.

```
settings.json          설정 (작업 목록과 각 작업의 예약)
history.jsonl          작업 이력. 한 줄에 실행 한 건, 최근 200건 보관
logs\
  logrogue-20260928.log   프로그램 동작 로그. 날짜별, 14일 보관, 파일당 5MB 상한
```

- 0.1.x의 설정 파일은 처음 실행할 때 **"기본 작업"** 하나로 자동으로 옮겨집니다. 예약과 예전 작업 이력도 이어집니다. 새 형식으로 저장된 뒤에는 0.1.x에서 읽을 수 없으니, 되돌릴 가능성이 있다면 업데이트 전에 설정 파일을 복사해두세요.
- 설정 파일이 손상되면 기본값으로 시작하고, 손상된 파일은 `settings.json.broken-날짜시각`으로 보관합니다.

## 실행 환경

- Windows 10 / 11 (x64)
- .NET 10 (자체 포함으로 게시하면 별도 설치 불필요)

## 빌드와 배포

### 요구 사항

- Visual Studio 2022 (최신 업데이트) 또는 Visual Studio 2026
- **.NET 데스크톱 개발** 워크로드
- .NET 10 SDK

### 개발 중 실행

`LogRogue.sln`을 열고 `LogRogue.App`을 시작 프로젝트로 둔 뒤 F5.

> Ctrl+F5로 실행한 뒤 창을 닫으면 트레이에 남아 있습니다. 다음 빌드에서 exe가 잠겨 실패하므로 트레이 메뉴의 [종료]로 끄고 빌드하세요.

### 단일 실행 파일 게시

Visual Studio의 게시(폴더, win-x64, 자체 포함, 단일 파일)를 쓰거나, 솔루션 폴더에서:

```
dotnet publish LogRogue.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o LogRogue.App\bin\Release\net10.0-windows\publish\win-x64
```

결과물: `LogRogue.App\bin\Release\net10.0-windows\publish\win-x64\Log Rogue.exe`

- 두 방법의 출력 위치를 같게 맞춰두어야 설치 파일이 옛 exe를 담는 일이 없습니다.
- `PublishTrimmed`는 WinForms에서 지원되지 않으므로 사용하지 마세요.

### 설치 파일 만들기

[Inno Setup](https://jrsoftware.org)으로 `installer\LogRogue.iss`를 컴파일(F9)하면 설치 파일이 만들어집니다. 게시를 먼저 해야 합니다.

- 설치 중 프로그램이 실행 중이면 종료를 안내합니다.
- 제거 시 자동 실행 등록도 함께 지웁니다.
- 설정·이력·로그는 제거해도 남습니다.

> 서명하지 않은 실행 파일은 SmartScreen 경고가 뜨고 백신이 오탐할 수 있습니다. 트레이 상주 + 자동 실행 + 파일 삭제 조합이 행위 기반 탐지에 걸리기 쉽습니다.

### 배포 순서

1. 트레이에서 기존 프로그램 종료
2. `LogRogue.App.csproj`의 `FileVersion`과 설치 스크립트의 `AppVersion` 올리기
3. `LogRogue.App\bin\Release` 폴더 삭제
4. 게시
5. 설치 파일 컴파일
6. 설치 후 정보 창에서 버전 확인

## 사용 방법

1. **추가**를 눌러 작업을 만듭니다. 대상 폴더와 출력 폴더를 지정하고, 기간·압축 단위·원본 처리를 고릅니다.
2. 예약을 쓰려면 편집 창의 **예약 설정...**에서 주기를 정합니다.
3. 바로 실행하려면 작업을 고르고 **지금 실행**을 누릅니다. 확인 창에서 만들어질 압축 파일 목록을 보고 시작합니다.
4. 결과는 아래 결과 목록과 **작업 이력**에서 확인합니다.

작업 목록에서 더블클릭하면 편집, 오른쪽 클릭하면 대상·출력 폴더 열기와 삭제가 나옵니다. 트레이 메뉴의 **지금 백업**에서도 작업을 골라 실행할 수 있습니다.

> 처음 사용할 때는 실제 로그 폴더를 복사한 사본으로 먼저 테스트하는 것을 권장합니다. 탐색기로 복사하면 수정한 날짜가 유지되므로 결과가 똑같이 나옵니다.

## 변경 이력

### 0.2.0

- **여러 작업 지원.** 메인 창을 작업 목록 중심으로 개편하고, 작업마다 설정과 예약을 따로 갖도록 변경
- **파일 수정 날짜 기준으로 판정.** 폴더 이름 대신 파일마다 수정한 날짜로 판정해 어떤 폴더 구조의 로그도 처리
- 원본 삭제를 파일 단위로 변경하고, 파일마다 안전 확인 추가. 비게 된 하위 폴더 정리
- 같은 이름으로 매일 새로 생기는 로그를 월별·주별 압축에서 모두 보존
- 위험한 대상 폴더 차단, 링크 따라가지 않음
- 작업 간 충돌(대상 겹침, 출력 공유, 출력이 다른 작업 대상 안) 차단
- 정보 창 추가 (버전, 개발자, 연락처, 데이터 폴더 바로가기)
- 표시 이름을 "로그로그"로 변경
- 메인 창 크기 고정, 긴 상태 메시지는 마우스를 올리면 전체 표시
- 수정: 한 번도 실행한 적 없는 예약이 영원히 실행되지 않던 문제
- 설정 파일 형식 변경 (0.1.x 설정은 자동 이전)
